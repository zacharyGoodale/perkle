# Plaid Insights: usefulness and pricing for Perkle

Researched October 30, 2026 using official Plaid documentation and its published OpenAPI schema. No paid API calls, product activation, sales contact, or application changes were made.

## Recommendation

**Do not add an Insights product to the benefit-classification spike yet.** Standard Transactions already provides the merchant/category/location/counterparty enrichments most relevant to the task. No examined Insights offering documents an issuer-benefit-credit label, benefit eligibility decision, or authoritative issuer-versus-merchant origin field. That last statement is a finding from the reviewed schemas, not a claim that Plaid could never offer additional private data.

The useful next experiment remains comparing Jev with the full original descriptions and existing Transactions metadata. Aggregate merchant/category/recurrence features can be computed locally from the history already retrieved, without assuming that another paid product supplies missing issuer provenance.

## What “Insights” might mean

### Financial Insights / Personal Finance Insights

This is a solution/product grouping, not one extra endpoint or one separately priced enrichment switch. Plaid groups Transactions, Recurring Transactions, Investments, Liabilities, and Enrich around financial-management use cases. Transactions already uses Plaid's ML enrichment engine for fields not supplied directly by institutions. Enrich uses the **same engine** for customer-supplied transactions from other sources. [Financial Insights comparison](https://plaid.com/docs/financial-insights/), [Personal Finance Insights solution](https://plaid.com/insights-solution/)

### Enrich

Enrich accepts raw transaction descriptions with amount, direction, currency, and account type, optionally location/MCC/date. It returns merchant, category, location, and counterparty context. It is aimed at transaction data generated by one's own banking products or obtained from non-Plaid sources; it is available in the US/Canada and requires product access. [Enrich overview](https://plaid.com/docs/enrich/), [API](https://plaid.com/docs/api/products/enrich/)

**Perkle fit:** low expected incremental value for records already supplied by Transactions. Enrich has some output details such as phone numbers, but these identify merchants rather than issuer benefit credits. It may be worth evaluating later if Perkle imports non-Plaid data; improved identification of current ambiguous credits is unproven.

**Price:** charged by transactions sent for enrichment, not merely by batch count. A request can contain up to 100 transactions. The exact rate is account/plan-specific and is shown during the Production access flow or available through sales; it is not published in the documentation. Thus a 289-transaction experiment costs `289 × quoted transaction rate`, subject to the account's actual terms. [Enrich pricing and integration](https://plaid.com/docs/enrich/)

### Beta User Insights / Merchant Insights

The official OpenAPI includes **`/beta/transactions/user_insights/v1/get`**, marked `x-hidden-from-docs: true`. Its summary says it obtains user insights from transactions sent through Enrich. The response describes merchant/category spending and inflow aggregates, inferred external account types, and recurring streams. `merchant_insights` is a list of top merchants with names/entity IDs, categories, counts, and inflow/outflow totals—not an endpoint for resolving any merchant ID or checking benefit participation. [Official schema](https://github.com/plaid/plaid-openapi/blob/master/2020-09-14.yml) (path and `TransactionsUserInsightsGetResponse`, `CounterpartyInsights`, `MerchantInsights` schemas)

**Perkle fit:** potentially useful for spending summaries or recurrence features, but no documented new per-credit issuer evidence. **Availability and price are unverified**: presence in a public schema does not establish general availability or entitlement on this account. No public numeric price or clearly documented billing model for this beta was found. Confirm directly with Plaid before planning an integration; do not assume it is free or included with Enrich.

### Asset Report with Insights

`/asset_report/get` accepts `include_insights: true`, adding cleaned merchant/category/location information to an asset report that otherwise returns bank descriptions. [Assets API](https://plaid.com/docs/api/products/assets/#asset_reportget)

**Perkle fit:** overlaps the transaction enrichment already collected; it is an asset-report workflow rather than a benefit detector. The reviewed docs do not publish a separate numeric Insights-addon price. Assets has flexible request pricing based on report scope/history. Do not infer that toggling `include_insights` is free. [Billing](https://plaid.com/docs/account/billing/)

### Consumer Report / Plaid Check Insights

Income Insights concerns income streams and forecasts; Cash Flow Insights covers aggregated cash-flow and volatility attributes; Network Insights concerns connection-history risk signals; Partner Insights provides Prism Data credit-risk scores. These are consumer-report/underwriting products, not card-benefit classification services. The Check API requires a consumer-report permissible purpose and additional user onboarding data; Plaid Check is available to US entities evaluating US consumers. [Consumer Report overview](https://plaid.com/docs/check/), [API](https://plaid.com/docs/api/products/check/)

**Perkle fit:** poor. No documented benefit-credit signal justifies this separate reporting workflow for the current tracker.

**Price/access:** no Plaid Check products are offered on Pay-as-you-go; Base Report and Income Insights are available on Growth/Custom, while other Check products require Custom. Exact amounts are not public. Depending on contract, billing is bundled or per product/report; Partner Insights has a distinct generation-time charging event. [Billing and plan restrictions](https://plaid.com/docs/account/billing/)

## Pricing conclusion

There is no defensible public dollar quote for “Plaid Insights.” First identify the product. Plaid explicitly says documentation has no price list; eligible Pay-as-you-go/Growth rates appear in the Production application and current plans can be inspected in the authenticated Dashboard. Custom rates require the account's commercial terms. [Official billing guidance](https://plaid.com/docs/account/billing/)

Root attempted read-only Dashboard access during this research, but it redirected to sign-in; no credentials were entered. Therefore this research cannot supply account-specific rates. The pricing page's “Included” product labels indicate plan availability, not zero marginal usage charges. [Pricing plans](https://plaid.com/pricing/)

For this spike, the strongest established distinction is that the relevant transaction enrichments are already returned by the existing Transactions integration. Buying Enrich or an Insights-branded workflow would need demonstrated incremental data or accuracy value, plus an actual account quote.
